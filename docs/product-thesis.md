# Product Thesis: Life Memory Ending App

## One Sentence

終活を「死後の手続き」から「本人の人生を整理し、意思と記憶を大切な人へ正しく渡す体験」へ変える、人生記録OSを作る。

## Why This Should Exist

一般的な終活サービスは、資産、保険、葬儀、連絡先、遺言などのチェックリストに寄りやすい。それらは必要だが、本人が何を大切にしてきたのか、家族に何を伝えたいのか、どの出来事が人生の意味を作ったのかは残りにくい。

このアプリは、事務的な終活情報と、本人の人生記憶を同じ場所で扱う。ただし同じ型には押し込まない。書類は書類として、記憶は記憶として、価値観は価値観として扱い、それらをAIが参照できる形で整理する。

PAIから学ぶべき点は、AIを便利機能として後付けするのではなく、ユーザーの現在状態と理想状態の差分を閉じるOSとして設計すること。このアプリでは、未整理の人生記憶と終活不安を、確認済みの記録、共有可能な説明、本人らしい対話へ変換する。

## Current State and Ideal State

### Current State

- 写真、メモ、会話、家族の記憶が散らばっている。
- 終活情報は事務的で、本人らしさが残らない。
- 家族は「何を聞けばよいか」がわからない。
- 本人も「何を残せばよいか」がわからない。
- AIに話せば整理はできるが、根拠、共有範囲、本人確認が曖昧になりやすい。

### Ideal State

- 人生の出来事、人物、価値観、意思、書類が整理されている。
- 本人が確認した記憶だけが、家族共有やAI応答の根拠になる。
- 家族は、事務情報だけでなく「なぜその意思なのか」を理解できる。
- 本人は、終活を恐怖や義務ではなく、自分の人生を見直す行為として進められる。
- Life Companionが、本人の言葉と記憶を尊重しながら、記録の整理と振り返りを手伝う。

## Product Layers

PAIの `PAI = OS`, `Pulse = Dashboard`, `DA = Interface` の分離を、このアプリでは以下に置き換える。

| Layer | Role | Initial Form |
|---|---|---|
| Life Memory OS | 記憶、意思、書類、共有範囲、AI根拠の中核 | データモデル、保存、検索、権限 |
| Memory Space | 記憶を眺め、探し、関係を理解するUI | 一覧、年表、人物ビュー、グラフ |
| Life Companion | 本人の記録をもとに会話するAI人格 | 初回インタビュー、要約、想起補助 |

この三層は混ぜない。UIの見た目が先行しても、OS層の信頼度と共有範囲が崩れるなら採用しない。AI人格が魅力的でも、根拠のない断定をするなら採用しない。

## Product Principles

### 1. 終活はチェックリストではなく人生編集である

必要書類を集めるだけでは不十分。本人が何を大切にしたか、誰に何を伝えたいか、どんな言葉で残したいかを扱う。

### 2. AIは本人の代弁者ではなく整理者から始める

初期のLife Companionは、本人の代わりに意思決定しない。質問し、分類し、要約し、未確認点を出し、本人確認を求める。

### 3. 確認済み記憶と推測を混ぜない

AIが推測した感情、関係、意味づけは便利だが危険でもある。データ構造とUIで `raw`, `ai_suggested`, `principal_confirmed`, `share_ready` を分ける。

### 4. 共有範囲は後付け設定にしない

記憶には最初から共有範囲を持たせる。完全非公開、本人のみ、家族共有、代理人共有、死後共有、公開可能を分ける。

### 5. 3D記憶空間は探索用、編集は確実な2D UI

記憶玉やグラフは、関係性や全体像を感じるために有効。ただし日付、共有範囲、本人確認、書類添付などは2Dフォームとレビュー画面で扱う。

### 6. 家族が読める言葉にする

本人とAIだけが理解できる記録では価値が半減する。各記憶には、家族向けの短い説明、関連人物、背景、確認状態を持たせる。

### 7. 法的・医療的・財務的な断定を避ける

このアプリは記録と整理の道具であり、専門家の代替ではない。法務・税務・医療・介護の領域では、専門家確認が必要な状態を明示する。

## Target Users

### Primary: 本人

人生を整理したい人。高齢者に限らず、病気、介護、家族構成の変化、創業者の事業承継、宗教・思想・作品の継承なども対象になる。

### Secondary: 家族・近しい人

本人の意思、思い出、関係性、必要手続きを理解したい人。本人の記録を勝手に編集するのではなく、質問、補足、確認依頼ができる存在。

### Tertiary: 支援者

士業、医療・介護者、宗教者、葬儀・相続支援者など。初期スコープでは深く作り込まず、将来的な共有先として考える。

## Initial Jobs To Be Done

- 自分の人生で大切だった出来事を、無理なく思い出して整理したい。
- 家族に何を伝えればよいか、質問されながら考えたい。
- 写真やメモを、人物や出来事に結びつけたい。
- 終活に必要な情報と、人生の物語を分けつつつなげたい。
- 家族に見せてよい記憶と、見せたくない記憶を分けたい。
- AIに自分のことを話す時、勝手に話を作らず、根拠を示してほしい。

## Non-Goals For Early Versions

- 法的に有効な遺言書の自動作成
- 死後の自動送信やSNS投稿
- 常時監視daemon
- 音声クローンや本人そっくりの完全な人格再現
- すべての情報を3D UIで編集する体験
- 家族間トラブルの自動仲裁
- 医療、税務、法律の専門判断

## Product Surface

初期プロダクトは、以下の画面で成立させる。

| Surface | Purpose |
|---|---|
| Onboarding Interview | 本人、分身名、目的、最初の記憶を作る |
| Memory Inbox | 未整理素材を置く |
| Memory Capsules | 確認済み記憶を管理する |
| People | 関係人物を整理する |
| Timeline | 人生の流れで見る |
| Memory Graph | 記憶同士の関係を探索する |
| Legacy Packets | 家族や代理人へ渡す情報束を作る |
| Companion Chat | 記録に基づいて振り返り、整理する |

## Success Criteria

初期版の成功は、機能数ではなく以下で測る。

- 本人が最初の30分で3つ以上の記憶カプセルを作れる。
- 各記憶に、共有範囲と確認状態が必ず付く。
- AIの要約に対して、本人が修正・承認できる。
- 家族向けに読めるLegacy Packetを1つ作れる。
- AI応答から根拠記憶へ戻れる。
- 未整理記憶、確認待ち記憶、共有準備済み記憶が区別できる。

## PAI Lessons Adopted

| PAI Lesson | App Translation |
|---|---|
| OS / Dashboard / Assistantの分離 | Life Memory OS / Memory Space / Life Companion |
| Current -> Ideal | 未整理の人生記録から、確認済みで共有可能な記録へ |
| WORK / LEARNING / KNOWLEDGE | Raw Capture / Episode / Insight / Canonical Memory |
| Interview skill | 初回体験をフォームではなく会話にする |
| Graph focus interaction | 記憶玉の近傍関係を探索する |
| public/private命名規則 | 共有範囲をデータ構造とUIに埋め込む |
| daemonは後回し | 初期は明示的な保存と同期に限定する |
