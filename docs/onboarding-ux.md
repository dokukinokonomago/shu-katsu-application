# Onboarding UX

## Goal

初回体験の目的は、ユーザーに設定を完了させることではない。本人が「このアプリは自分の人生を丁寧に扱う場所だ」と理解し、最初の記憶を安全に残せる状態にすること。

PAIのオンボーディングは、インストールからDA identity、TELOS、interviewへ進む。これを終活・人生記録アプリでは、分身名、本人文脈、人生の目的地、最初の記憶カプセルへ置き換える。

## Onboarding Promise

初回画面で伝えるべきこと:

- ここでは、事務的な終活情報だけでなく、人生の記憶も整理する。
- AIは勝手にあなたの意思を決めない。
- 共有範囲は記憶ごとに選べる。
- 未確認のAI要約と、本人確認済みの記録は分けて扱う。
- 最初は数分で、3つの記憶から始められる。

## Flow Overview

```text
Welcome
  -> Safety and privacy baseline
    -> Principal profile
      -> Life Companion naming
        -> Purpose interview
          -> First 3 memories
            -> Review and confirm
              -> Memory Space preview
```

## Step 1: Welcome

目的は世界観の提示。マーケティング的な長文ではなく、実際の入力へすぐ進める。

画面要素:

- アプリ名または仮称
- 「人生の記憶と意思を、確認できる形で残す」程度の短い説明
- `はじめる`
- `後で読む: 共有とAIの扱い`

避けること:

- 終活の不安を過度に煽る。
- いきなり大量の機能説明をする。
- 3D記憶空間を主役にしすぎる。

## Step 2: Safety and Privacy Baseline

最初に安心の境界を置く。

確認項目:

- AIの下書きは本人確認前に確定記録にならない。
- 家族共有はユーザーが選ぶ。
- 法務、税務、医療の専門判断はこのアプリだけでは完結しない。
- いつでも非公開に戻せる設計にする。

UX:

- 長い規約ではなく、4つの短い約束として表示する。
- 同意チェックは1つでよいが、後から設定で再確認できる。

## Step 3: Principal Profile

本人の基本文脈を作る。フォームは最小限にし、会話に進める。

最小入力:

- 呼ばれたい名前
- 生年または年代
- 主な居住地域
- 家族・近しい人を登録するかどうか
- このアプリを使う理由

任意入力:

- 職業・活動歴
- 信仰・思想・大切にしている習慣
- 作品、事業、地域活動など残したいもの

## Step 4: Life Companion Naming

PAIのDA identityを転用する。AIに名前を付けることで、道具ではなく「記憶整理を手伝う相手」になる。

入力:

- Life Companionの名前
- 口調: 丁寧、穏やか、簡潔、聞き役中心
- 距離感: 家族のように、秘書のように、編集者のように

重要な制約:

- 本人そのものを完全再現するとは言わない。
- 初期は「分身」より「伴走者」「記憶編集者」に近い説明にする。
- 本人確認済み記憶が増えた後に、本人らしい言葉遣いへ調整する。

## Step 5: Purpose Interview

PAIのTELOSに相当する部分。終活では、理想状態を「何を残したいか」「誰に何を渡したいか」として聞く。

1問ずつ聞く。ユーザーにスキーマを意識させない。

質問例:

1. このアプリに最初に手伝ってほしいことは何ですか。
2. 誰に、どんなことを残したいですか。
3. 今のうちに整理しておきたい不安はありますか。
4. あなたの人生で、誤解されたくないことはありますか。
5. 家族や近しい人に、いつか伝えたい言葉はありますか。
6. 残したくない、または今は触れたくない領域はありますか。

AIは回答から以下を抽出する。

- primary_goal
- intended_audience
- sensitive_topics
- first_packet_candidate
- tone_preference
- unresolved_questions

## Step 6: First 3 Memories

初回の完了条件は、プロフィール入力ではなく記憶カプセルを作ること。

3つの入口を用意する。

| Prompt | Target |
|---|---|
| 大切な人について1つ話す | person / episode |
| 人生で忘れたくない出来事を1つ話す | episode |
| 家族に残したい考えを1つ話す | value / wish |

各記憶で聞くこと:

- 何がありましたか。
- 誰が関係していますか。
- いつ頃のことですか。不明でもよい。
- その記憶を、誰に見せてもよいですか。
- AIの要約を確認しますか。

## Step 7: Review and Confirm

AIがMemory Capsuleの下書きを作り、本人が確認する。

レビュー画面:

- タイトル
- 3行要約
- 本文
- 関連人物
- 感情・価値観の候補
- 共有範囲
- 未確認点

操作:

- `確認済みにする`
- `下書きのまま保存`
- `非公開にする`
- `修正する`
- `この話は今は扱わない`

この時点で、確認済みと下書きの違いをUIで明確にする。

## Step 8: Memory Space Preview

最後に、小さなMemory Spaceを見せる。PAIのPulseのように、ユーザーが「これから育つ場所」を感じられるようにする。

初回プレビュー:

- 中心に本人
- 周囲に最初の3つの記憶
- 人物、価値観、出来事の色分け
- 未確認のものは点線または薄い表示
- クリックで詳細に戻れる

注意:

- 初回から3D操作を必須にしない。
- 一覧、年表、グラフの切替を用意する。
- 高齢者向けには一覧を主導線にする。

## Progressive Disclosure

最初に全部聞かない。終活情報は心理的負荷が高い。

| Timing | Ask |
|---|---|
| 初回 | 名前、目的、最初の3記憶、共有範囲 |
| 2回目以降 | 人物、写真、人生時期 |
| 記憶が増えた後 | Legacy Packet作成 |
| 信頼形成後 | 医療、介護、葬儀、資産の希望 |
| 後期 | 家族招待、代理人共有、専門家連携 |

## Empty States

空状態は説明ではなく、次の行動を示す。

| Empty Area | CTA |
|---|---|
| Memory Inbox | 写真、音声、メモを追加 |
| People | 大切な人を1人追加 |
| Timeline | 年代を1つ選んで思い出す |
| Legacy Packets | 家族に渡したいテーマを選ぶ |
| Companion Chat | 最近思い出したことを話す |

## Accessibility and Tone

終活アプリは、派手さより安心感と明瞭さを優先する。

- 文字は小さくしすぎない。
- 操作は戻せる。
- 危険操作には確認を挟む。
- 「死」を直接扱う画面では、軽すぎる演出を避ける。
- 家族向け共有画面では、本人の言葉とAI要約を区別する。
- ユーザーを急かす文言を避ける。

## Metrics

オンボーディングの成功指標:

- 初回で1つ以上のMemory Capsuleが保存される。
- 3つの記憶作成率。
- AI要約の修正率。
- 共有範囲が未設定の記憶がない。
- 初回離脱箇所。
- 初回後7日以内の再訪。
- Legacy Packet作成への到達率。

## Risks

| Risk | Mitigation |
|---|---|
| 重すぎて始められない | 最初は3記憶だけにする |
| AIが勝手に意味づけする | inferenceを本文と分離し、本人確認を必須にする |
| 家族共有が怖い | privateを初期値にし、明示的に広げる |
| 終活チェックリスト化する | 記憶、人物、価値観を初回に含める |
| 3D UIが使いにくい | 一覧と年表を主導線にする |
